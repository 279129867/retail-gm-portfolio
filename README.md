## 为什么是这三个模型

零售总经理的账，本质上是三层：

1. **单店能不能活** —— 开一家店投多少钱、多久回本、卖多少不亏；
2. **新渠道能不能加** —— 一场直播投多少、什么场观才保本；
3. **钱到底谁带来的** —— 全域 GMV 的增量归属，决定预算往哪挪。

三层对应三个文件，共用一套口径。任何一层算不清，另外两层都是猜。

需要 Python 3.10+。

```bash
git clone <本仓库地址>

```

三种用法，从轻到重：

```bash

# 2) 起页面：浏览器打开 http://localhost:8501
```

Windows 用户可直接双击 `启动.bat`（内含解释器路径，按自己环境改一行即可）。

## 模型一：单店单元经济

输入 15 个假设，输出坪效、人效、盈亏平衡、静态回本期。基准值对应一家 420㎡、月销 78 万的家居门店。

| 输入 | 基准 | 输入 | 基准 |
|---|---|---|---|
| 面积 | 420 ㎡ | 月租金 | 25,200 元 |
| 编制 | 9 人 | 人均月成本 | 6,500 元 |
| 综合毛利率 | 37% | 月销售额 | 780,000 元 |
| 客单价 | 8,600 元 | 到店转化率 | 21% |
| 建店投入 | 1,550,000 元 | 总部费率 | 2% |

核心公式：

```
月固定费用 = 租金 + 编制×人均成本 + 水电 + 推广
月变动费用 = 销售额×(提成率 + 交付成本率 + 总部费率)
月经营利润 = 销售额×毛利率 − 月变动费用 − 月固定费用
盈亏平衡月销 = 月固定费用 ÷ (毛利率 − 变动费率)
静态回本期 = 建店投入 ÷ 月经营利润
```

基准结果：月利润 **77,400 元**、净利率 **9.9%**、坪效 **1,857 元/㎡**、盈亏平衡月销 **464,082 元**、安全边际 **40.5%**、回本 **20.0 个月**。

## 模型二：直播盈亏平衡

一场家居直播的漏斗：曝光 → 进入 → 停留 → 点商品卡 → 下单，再扣退款。

```
成交单数 = 曝光×进房率×停留率×点卡率×下单率
净成交额 = 成交额×(1 − 退款率)
毛利     = 净成交额×毛利率
单场利润 = 毛利 − (投流 + 主播 + 运营 + 场地摊销 + 样机损耗)
保本场观 = 单场固定成本 ÷ (毛利率×每曝光净产出)
```

基准结果：单场 GMV **148,262 元**、净额 **106,749 元**、利润 **23,995 元**、保本场观 **29,280 人次**、单均获客成本 **431 元**。

这个模型真正的作用不是算利润，而是回答一句：**"场观掉到多少，这场就别播了？"**

## 模型三：全域 GMV 归因

| 渠道 | 成交额 | 投放 | 占比 | ROI | 增量 ROI |
|---|---|---|---|---|---|
| 自然到店 | 168.0 万 | 0 | 47.1% | — | — |
| 线上投放 | 76.0 万 | 8.6 万 | 21.3% | 8.84 | 3.09 |
| 老客转介绍 | 52.0 万 | 1.8 万 | 14.6% | 28.89 | 18.89 |
| 整装渠道 | 61.0 万 | 4.2 万 | 17.1% | 14.52 | 5.00 |

全区域合计 GMV **357.0 万**、投放 **14.6 万**、混算 ROI **24.45**、混算增量 ROI **17.10**。

两个口径必须同时看：**ROI 回答"这个渠道带来了多少"，增量 ROI 回答"多投这一笔多带来多少"**。只看前者，会把自然到店的老本算成投放的功劳，进而把预算持续投向效率最低的口子。

## 面试怎么讲

一句话开场，然后直接动手：

> "这家店 420 平、月销 78 万，净利率 9.9%、20 个月回本——先把租金调高 20%，看看还开不开。"

三步：

1. **改一个最敏感的参数**（租金或转化率），看回本期怎么变；
2. **加上限**（回本期超过 36 个月就不做），把判断变成规则；
3. **再挪到归因**（省下来的钱该投哪个渠道），用增量 ROI 收尾。

## 口径与边界

- 全部默认值为**行业区间中位假设**，不是任何一家公司的真实经营数据；
- 四份文档中的金额、门店数均为示例口径，已在各自「数据口径与局限」章节标注；
- 直播漏斗的进房率、停留率、退款率为平台侧经验值，属假设而非实测；
- 仓库代码可自由参考；文档与案例数据版权保留，转载前请联系作者。

如果这套模型对你有用，欢迎开 issue 指出口径问题——口径错误比数字错误更值得讨论。
